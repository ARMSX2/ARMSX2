# ARMSX2 iOS Build Setup

The iOS Xcode project is generated by CMake. It is not committed to the
repository because Xcode project output contains machine-local build paths and
can become stale quickly.

Swift UI sources live in:

```sh
platforms/ios/Swift
```

The iOS CMake entry point lives in:

```sh
platforms/ios/CMakeLists.txt
```

## Requirements

- macOS with Xcode installed
- Xcode command line tools selected with `xcode-select`
- CMake 4.4 or newer
- Ninja (`brew install ninja`)
- A recursive clone with submodules initialized

## Clone

```sh
git clone --recursive -b armsx2-ios https://github.com/ARMSX2/ARMSX2.git
cd ARMSX2
git submodule update --init --recursive
```

## Generate the Xcode Project

```sh
./scripts/generate-ios-xcode.sh
```

This creates:

```sh
build/device/ARMSX2iOS.xcodeproj
```

Open it with:

```sh
open build/device/ARMSX2iOS.xcodeproj
```

Use the `ARMSX2iOS` scheme.

## Build an Unsigned IPA

For sideloading or external resigning:

```sh
./scripts/build-ios-ipa.sh
```

The IPA is written to:

```sh
build/device/ARMSX2-iOS-unsigned.ipa
```

For a quicker development build, `./scripts/build-ios-ipa.sh --fast` compiles
the Swift UI at `-Onone`. It builds in `build/device-fast`, writes
`ARMSX2-iOS-development.ipa` there and shares `build/core-device`.

## Automatic Signing

If you have an Apple developer team and want Xcode automatic signing, regenerate
with your team and bundle identifier:

```sh
TEAM_ID=YOUR_APPLE_TEAM_ID BUNDLE_ID=com.your.bundle.id ./scripts/generate-ios-xcode.sh
```

Then open the generated project in Xcode and build the `ARMSX2iOS` scheme for an
iOS device.

## The Prebuilt Core

The PCSX2 core, `common/` and the 3rdparty libraries are not part of the Xcode
project. They build with Ninja into `build/core-sim`, `build/core-device` and
`build/core-catalyst`, and the app links them from there. Every app build runs
`scripts/build-ios-core.sh <platform>` first, which does nothing when no core
source changed.

The core is always a Release build with debug info and no LTO, one per platform
for every app configuration. Product > Clean Build Folder cleans the app only.
To rebuild the core from scratch, remove its directory:

```sh
rm -rf build/core-device
```

Core files are not in the Xcode project, so to set a breakpoint in one, open it
with File > Open, or use `breakpoint set -f <file> -l <line>` in lldb. Expect
some variables to be optimised out.

The project no longer regenerates itself. Re-run the generate script after
adding or removing Swift files or shader presets.

## Notes

- `build/` is generated output and should not be committed.
- The build target is iOS device arm64 by default.
- Minimum iOS version is 17.4.
- JIT availability depends on how the app is signed and launched. Unsigned IPAs
  may need to be resigned or launched with a compatible sideloading/debug setup.
- Do not rename low-level iOS JIT/runtime symbols unless you are intentionally
  changing that code path. Some internal names are compatibility plumbing and are
  not user-facing branding.
